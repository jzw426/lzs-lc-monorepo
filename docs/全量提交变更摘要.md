## 2 关键变更内容

### 2.1 工程与工具链

1. 建立 pnpm workspace 六包结构：core、content、platform、client、server、tools。
2. 锁定 Node.js 22.20.0、pnpm 11.6.0、TypeScript 5.9.3，启用严格模式与 `frozen-lockfile`。
3. 统一 ESLint 依赖边界规则，core 禁止引入 LayaAir、平台 API、Node API、墙钟时间与非种子随机数。
4. 统一 Prettier 与编辑器配置，提供 `.env.example` 与 `.gitignore`。

### 2.2 确定性核心与内容体系

1. core 实现 xoshiro128\*\* 种子随机数、30 tick/s 模拟循环、规范命令排序、快照续跑与回放校验。
2. 征兵规则固定“容量 → 费用 → 一次随机抽样”顺序，拒绝时不写经济状态。
3. content 提供 JSON Schema、AJV 校验、配置哈希与 4 个兵种基线，`configHash=fnv1a32:e7ae79c0`。
4. 黄金回放样本固定 `stateHash=fnv1a32:92852f6a`、tick=8、events=6。

### 2.3 服务端与外部依赖

1. server 提供健康检查、版本接口、回放校验接口，以及统一错误结构与请求追踪。
2. 幂等存储同时支持内存与 PostgreSQL，同键同体重放、同键异体返回 409。
3. 迁移脚本包含校验和防篡改检查，重复执行不重复应用。
4. Compose 编排 PostgreSQL 16.10、Redis 7.4.2 与 server，配置健康检查、持久卷与独立迁移 profile。
5. 镜像采用多阶段构建，`pnpm deploy --prod --legacy` 生成生产依赖，运行用户为非 root。

### 2.4 CI/CD 与客户端边界

1. CI 覆盖格式、Lint、类型检查、测试、覆盖率、构建、内容校验与黄金回放，并上传覆盖率产物。
2. 发布工作流仅手动触发，限定 staging/production，使用环境保护，镜像推送 GHCR，不包含生产部署动作。
3. client 仅接收快照与事件，提供 LayaAir 版本断言，不直接依赖平台 SDK。
