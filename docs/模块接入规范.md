# 《鲁智深与林冲》模块接入规范

| 项目     | 内容                                   |
| -------- | -------------------------------------- |
| 文档编号 | LZS-MODULE-SPEC-001                    |
| 版本     | v1.0                                   |
| 适用阶段 | M1 工程底座及后续阶段                  |
| 维护责任 | 工程底座实施组                         |
| 关联文档 | 开发指南、M1 验收标准、M1 阶段验收报告 |

## 1 目的与基本原则

本规范定义新业务模块、新规则、新内容、新接口和新平台能力的接入方式，确保底座长期满足可扩展、可复用、易维护要求。

四项原则：

1. **规则唯一**：经济、随机与战斗判定只在 core 实现，客户端和服务端不得复制。
2. **边界优先**：跨包只通过公开导出交互，禁止引用其他包内部文件。
3. **协议先行**：新增命令、事件、配置或接口必须先定义数据协议，再写实现。
4. **证据闭环**：任何接入必须附带自动化测试与可重复的验证命令。

## 2 包边界矩阵

| 调用方   | 允许依赖       | 禁止依赖                                                  |
| -------- | -------------- | --------------------------------------------------------- |
| core     | 无             | client、server、platform、content、tools、Node 与平台 API |
| content  | core           | client、server、platform、tools                           |
| platform | 无             | core、content、client、server、tools                      |
| client   | core、platform | server、tools                                             |
| server   | core、content  | client、platform                                          |
| tools    | core、content  | client、server、platform                                  |

约束由 ESLint `no-restricted-imports` 执行。新增包必须同步补充边界规则，否则视为未完成接入。

## 3 接入流程总览

| 步骤 | 动作                           | 产出              |
| ---- | ------------------------------ | ----------------- |
| 1    | 明确模块归属与依赖方向         | 模块说明          |
| 2    | 定义类型、命令、事件或接口协议 | 类型文件或 Schema |
| 3    | 在 core 或对应层实现逻辑       | 实现代码          |
| 4    | 补齐成功、失败与边界测试       | 测试用例          |
| 5    | 更新黄金样本或内容哈希         | 基线文件          |
| 6    | 通过本地门禁并提交评审         | 验证记录          |

## 4 新增业务规则

以新增一条核心规则为例，接入顺序固定如下。

### 4.1 定义协议

1. 在 `packages/core/src/types.ts` 增加命令类型，并加入 `GameCommand` 联合类型。
2. 在事件联合类型中增加对应事件，事件必须包含 `tick`、`sequence`、`commandId`。
3. 命令字段只允许可序列化的整数、字符串与枚举，禁止函数、类实例和时间对象。

### 4.2 实现规则

1. 在 core 内新增纯函数或方法，输入为状态副本与配置，输出为结果对象。
2. 所有拒绝原因必须使用明确枚举值，不得用字符串拼接表达。
3. 失败路径不得写入状态、不得消耗随机数、不得改变事件序号以外的副作用。
4. 多步校验顺序必须固定，并在注释中写明顺序。

### 4.3 接入模拟循环

1. 在 `GameSimulation` 的命令分派处增加分支，未知命令必须抛出明确错误。
2. 保持命令排序规则不变：`sequence` 升序，再按 `commandId` UTF-16 码元升序。
3. 事件序号必须继续由 `nextEventSequence` 统一分配，禁止另建计数器。

### 4.4 测试与基线

1. 覆盖成功路径、每个拒绝原因、重复命令和非法参数。
2. 若规则影响状态，新增黄金回放样本或在现有样本中增加命令。
3. 通过 `pnpm run replay:golden` 固定新的 `stateHash`。

## 5 新增兵种与内容

### 5.1 内容结构

内容清单位于 `packages/content/content/baseline/manifest.json`，字段约束由 JSON Schema 定义：

| 字段                       | 约束                             |
| -------------------------- | -------------------------------- |
| `contentVersion`           | 内容版本，变更内容必须递增       |
| `rulesVersion`             | 规则版本，变更判定逻辑必须递增   |
| `configHash`               | 真实内容哈希，必须由校验命令生成 |
| `tickRate`                 | 固定 30，不得修改                |
| `economy.initialGrain`     | 非负整数                         |
| `economy.barracksCapacity` | 1–100 的整数                     |
| `economy.recruitCost`      | 非负整数                         |
| `units[].id`               | 全局唯一，非空                   |
| `units[].name`             | 刀 / 枪 / 骑 / 弓                |
| `units[].attack`           | 正整数                           |
| `units[].maxHealth`        | 正整数                           |

### 5.2 接入步骤

1. 增加单位或调整经济值。
2. 运行 `pnpm run validate:content`，按报错提示更新 `configHash`。
3. 运行 `pnpm run replay:golden`，确认回放结果变化符合预期。
4. 若影响既有玩法数据，必须同步递增版本号并在评审中说明兼容影响。

注意：当前数值是 M1 工程基线，不是正式平衡值。调整数值不等于完成平衡验收。

## 6 新增平台能力

1. 在 `packages/platform/src/ports.ts` 定义能力接口，返回值必须可判别成功与失败。
2. 在 `MockPlatformAdapter` 中实现对应能力，并纳入 `PlatformCapability` 枚举。
3. 未显式启用的能力必须抛出 `PlatformUnavailableError`，禁止返回伪造成功值。
4. 调用方通过 `ClientRuntime.platform` 访问，不得直接引入平台 SDK。
5. 真实平台适配器必须在真机环境验证后才能纳入验收范围。

## 7 新增服务接口

### 7.1 接口约定

| 项目     | 要求                                      |
| -------- | ----------------------------------------- |
| 路径     | `/api/v1/` 前缀，资源名使用复数           |
| 方法     | 读写语义清晰，禁止用 GET 修改状态         |
| 入参校验 | 使用 Fastify Schema，限制类型、长度与上限 |
| 追踪     | 响应必须包含 `x-request-id`               |
| 错误     | 使用统一错误码结构，不泄露内部堆栈        |
| 版本     | 涉及回放、结算的接口必须校验四个版本字段  |
| 幂等     | 写接口必须要求 `Idempotency-Key`          |
| 日志     | 敏感头与连接串必须脱敏                    |

### 7.2 现有错误码

| 状态码 | 错误码                 | 含义                 |
| ------ | ---------------------- | -------------------- |
| 400    | `INVALID_REQUEST`      | 请求结构校验失败     |
| 400    | `INVALID_REPLAY`       | 回放参数非法         |
| 409    | `IDEMPOTENCY_CONFLICT` | 同键不同请求体       |
| 409    | `VERSION_MISMATCH`     | 版本或配置哈希不一致 |
| 422    | `REPLAY_MISMATCH`      | 回放状态哈希分歧     |
| 500    | `INTERNAL_ERROR`       | 未处理的服务错误     |

新增错误码必须同步更新本节和服务端测试。

### 7.3 可信数据原则

服务端不得信任客户端提交的经济、卡池、规则版本或费用参数。涉及规则计算的接口必须使用服务端内容包重建配置，仅接受种子、命令序列等不可推导输入。

## 8 客户端视图接入

1. 视图实现 `BattleView` 接口，只接收快照与事件，不得持有 `GameSimulation` 可变状态。
2. 每帧通过 `ClientRuntime.advanceTick()` 推进，禁止视图直接调用 core。
3. 视图异常由 `onViewError` 捕获，不得导致核心模拟中断或重置。
4. LayaAir 接入前调用 `assertLayaAirVersion('3.3.0')`，版本不一致必须失败。
5. 平台能力统一从 `ClientRuntime.platform` 获取，未启用能力必须走显式失败分支。

## 9 新增 workspace 包

1. 在 `pnpm-workspace.yaml` 覆盖范围内创建目录与 `package.json`，包名使用 `@lzs/` 前缀。
2. `tsconfig.json` 继承 `tsconfig.base.json`，输出到 `dist`，声明与 sourcemap 保持开启。
3. `exports` 指向 `dist`，并提供 `types` 条件。
4. 在根 `build`、`typecheck`、`test` 命令覆盖范围内即可被自动发现，无需修改根脚本。
5. 在 ESLint 中补充该包的依赖边界规则。
6. 若包含第三方构建脚本，必须在 `allowBuilds` 中显式批准并说明原因。

## 10 接入评审清单

提交评审前逐项确认：

- [ ] 模块归属与依赖方向符合第 2 节矩阵。
- [ ] 命令、事件、接口或内容协议已定义并可序列化。
- [ ] 业务规则只在 core 实现，客户端与服务端无复制逻辑。
- [ ] 成功、拒绝、重复与非法输入均有测试。
- [ ] 排序使用码元比较，未引入区域设置依赖。
- [ ] 未使用墙钟、非种子随机数或平台 API 进入 core。
- [ ] 内容变更已更新版本与真实 `configHash`。
- [ ] 黄金回放通过，且哈希变化有明确解释。
- [ ] 服务端接口包含 requestId、版本校验与幂等要求。
- [ ] 新增敏感日志字段已加入脱敏列表。
- [ ] `pnpm run ci` 通过。
- [ ] 未执行的外部环境验证已明确标注，未冒充通过。

## 11 禁止事项

1. 禁止在客户端或服务端复制征兵、费用、随机或战斗判定逻辑。
2. 禁止绕过内容校验直接读取未校验 JSON。
3. 禁止跳过 golden 样本更新流程直接修改 `expectedHash`。
4. 禁止用内存幂等替代 staging/production 的 PostgreSQL 幂等。
5. 禁止在未提供 Docker、真机或云端证据时宣称对应验证通过。
6. 禁止跨包引用 `src` 内部文件或未导出的符号。
