## 1 目的与适用范围

本指南面向首次参与《鲁智深与林冲》客户端、服务端、核心规则与内容开发的人员，用于统一环境准备、目录职责、开发命令、编码约定和本地验证方式。所有新增代码必须遵循本指南与《模块接入规范》，并通过《M1 验收标准》定义的门禁。

## 2 环境准备

### 2.1 版本要求

| 组件       | 版本    | 强制方式                                      |
| ---------- | ------- | --------------------------------------------- |
| Node.js    | 22.20.0 | `engines`、`.nvmrc`、`.node-version` 三处约束 |
| pnpm       | 11.6.0  | 根 `packageManager` 字段                      |
| TypeScript | 5.9.3   | 根 devDependencies 固定版本                   |

若本机默认 Node.js 版本不是 22.x，不要在项目内混用其他版本，使用以下临时链执行命令：

```text
npx --yes --package=node@22.20.0 --package=pnpm@11.6.0 --call "<命令>"
```

### 2.2 首次安装

```text
pnpm install
```

注意：

1. `.npmrc` 已启用 `engine-strict`、`strict-peer-dependencies`、`frozen-lockfile`，版本不符会直接失败，这是预期行为。
2. pnpm 11 默认禁止依赖执行构建脚本；`pnpm-workspace.yaml` 的 `allowBuilds` 已显式批准 `esbuild` 与 `protobufjs`，不要自行扩大批准范围。
3. 锁文件必须提交并保持与 `package.json` 同步，禁止在本地生成后不提交。

## 3 仓库结构

| 路径                | 包名            | 职责                                     | 允许依赖                     |
| ------------------- | --------------- | ---------------------------------------- | ---------------------------- |
| `packages/core`     | `@lzs/core`     | 确定性模拟、命令、事件、快照、回放、哈希 | 无（仅标准 TS 能力）         |
| `packages/content`  | `@lzs/content`  | 内容 Schema、校验、哈希、加载入口        | `@lzs/core`                  |
| `packages/platform` | `@lzs/platform` | 登录、广告、分享、存储、生命周期 Port    | 无                           |
| `packages/client`   | `@lzs/client`   | 运行时视图边界、LayaAir 适配边界         | `@lzs/core`、`@lzs/platform` |
| `packages/server`   | `@lzs/server`   | HTTP 接口、环境校验、幂等、迁移、遥测    | `@lzs/core`、`@lzs/content`  |
| `packages/tools`    | `@lzs/tools`    | 内容校验、回放、模拟 CLI                 | `@lzs/core`、`@lzs/content`  |

依赖方向由 ESLint 强制，不得通过相对路径绕过包边界引用其他模块内部文件。

## 4 常用命令

### 4.1 根级命令

| 命令                        | 作用                                                 |
| --------------------------- | ---------------------------------------------------- |
| `pnpm run build`            | 按拓扑顺序构建全部包                                 |
| `pnpm run typecheck`        | 先构建，再对六包执行 `tsc --noEmit`                  |
| `pnpm run lint`             | 全仓 ESLint，含依赖边界与 core 禁用规则              |
| `pnpm run format`           | Prettier 写入格式化                                  |
| `pnpm run format:check`     | Prettier 只检查，CI 使用                             |
| `pnpm run test`             | 先构建，再运行六包测试                               |
| `pnpm run test:coverage`    | 运行 core 覆盖率并应用门槛                           |
| `pnpm run validate:content` | 校验内容基线并输出真实 configHash                    |
| `pnpm run replay:golden`    | 校验黄金回放样本                                     |
| `pnpm run ci`               | 串联格式、Lint、类型、测试、覆盖率、构建、内容、回放 |

### 4.2 包级命令

```text
pnpm --filter @lzs/core build
pnpm --filter @lzs/server test
pnpm --filter @lzs/tools validate:content
pnpm --filter @lzs/tools replay:golden
pnpm --filter @lzs/tools run simulate --seed 42 --ticks 30 --recruits 7
```

`tools` 的模拟命令支持 `--seed`、`--ticks`、`--recruits`，输出成功征兵数、拒绝数与事件数，用于快速人工复核经济规则。

## 5 本地运行

### 5.1 核心与内容验证

```text
pnpm run build
pnpm run validate:content
pnpm run replay:golden
```

预期输出分别包含真实 `configHash` 与黄金 `stateHash`。两者必须与仓库记录一致，否则说明内容或规则被修改但基线未同步。

### 5.2 启动服务

```text
pnpm --filter @lzs/server start
```

启动前按第 6 节配置环境变量。local/test 默认使用内存幂等存储；staging/production 强制 PostgreSQL，缺少依赖会直接启动失败。

### 5.3 接口自测

```text
curl http://127.0.0.1:3000/health/live
curl http://127.0.0.1:3000/health/ready
curl http://127.0.0.1:3000/api/v1/version
```

回放校验必须携带 `Idempotency-Key`：

```text
curl -X POST http://127.0.0.1:3000/api/v1/replays/verify \
  -H "content-type: application/json" \
  -H "idempotency-key: local-001" \
  --data-binary @packages/tools/fixtures/golden-replay.json
```

## 6 环境变量

| 变量                          | 必填                     | 默认                   | 约束                                        |
| ----------------------------- | ------------------------ | ---------------------- | ------------------------------------------- |
| `APP_ENV`                     | 否                       | `local`                | local / test / staging / production         |
| `HOST`                        | 否                       | `127.0.0.1`            | 非空                                        |
| `PORT`                        | 否                       | `3000`                 | 1–65535 的整数                              |
| `LOG_LEVEL`                   | 否                       | `info`                 | fatal / error / warn / info / debug / trace |
| `GAME_VERSION`                | staging、production 必填 | 本机默认 `0.1.0-m1`    | 非空                                        |
| `IDEMPOTENCY_STORE`           | 否                       | local/test 为 `memory` | staging/production 仅允许 `postgres`        |
| `DATABASE_URL`                | postgres 模式必填        | 无                     | `postgres:` 或 `postgresql:`                |
| `REDIS_URL`                   | staging、production 必填 | 无                     | `redis:` 或 `rediss:`                       |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | 否                       | 无                     | `http:` 或 `https:`，配置后启用追踪         |
| `OTEL_SERVICE_NAME`           | 否                       | `lzs-server`           | 服务标识                                    |

配置校验在启动时执行，不允许静默回退。日志已对 `authorization`、`cookie`、`idempotency-key`、`DATABASE_URL`、`REDIS_URL` 做脱敏。

## 7 编码规范

1. 全仓 TypeScript 严格模式，禁止 `any`、非空断言（测试文件除外）与隐式返回。
2. 类型导入使用 `import type`，避免运行期副作用。
3. 业务注释、错误信息、文档使用简体中文；标识符使用英文。
4. 排序必须使用 UTF-16 码元比较，禁止使用可能受区域设置影响的 `localeCompare`。
5. 不在 core 中使用 `Date.now`、`Math.random`、Laya、Node 或平台 API。
6. 错误信息必须可定位，避免只抛出字符串常量。
7. 新增文件遵循现有目录命名，不使用未接入构建的散落脚本。

## 8 core 确定性约定

| 约定 | 要求                                           |
| ---- | ---------------------------------------------- |
| 时间 | 只接受显式 tick，禁止墙钟                      |
| 随机 | 仅使用 `Xoshiro128StarStar`，种子为 uint32     |
| 状态 | 使用安全整数，禁止浮点累积                     |
| 命令 | 按 `sequence` 升序，再按 `commandId` 码元升序  |
| 事件 | 每个命令产生一个事件，事件序号单调递增         |
| 快照 | 快照必须可完整恢复模拟，包括随机数状态         |
| 回放 | 同配置、同命令、同种子必须得到同一 `stateHash` |
| 幂等 | 重复 `commandId` 必须拒绝且不改变经济状态      |
| 哈希 | FNV-1a 32 仅用于一致性，不得用于安全校验       |

经济规则执行顺序固定为容量、费用、一次随机抽样。任何失败路径不得写经济状态、不得推进随机数。

## 9 测试要求

1. 每个包使用 Vitest，测试文件命名为 `*.test.ts`，放在包内 `test/` 目录。
2. core 覆盖率门槛：语句与行不低于 90%，分支不低于 85%，函数不低于 90%；当前实际值高于门槛，不得下调。
3. 经济与随机路径必须同时覆盖成功与拒绝分支。
4. 涉及排序、快照、回放的行为变更，必须新增或更新黄金样本。
5. 属性测试优先使用 `fast-check` 描述不变量，而不是堆叠固定用例。

## 10 内容修改流程

1. 修改 `packages/content/content/baseline/manifest.json`。
2. 运行 `pnpm run validate:content`，校验失败时会输出期望的真实 `configHash`。
3. 将期望哈希写回清单，再次校验直到通过。
4. 若单位或经济值变化影响回放结果，重新生成黄金样本并更新 `expectedHash`。
5. 同步更新 `contentVersion` 或 `rulesVersion`，并在提交说明中注明影响范围。

禁止手工拼接或复用旧哈希绕过校验。

## 11 常见问题

| 现象                    | 原因                    | 处理                                     |
| ----------------------- | ----------------------- | ---------------------------------------- |
| 安装提示引擎版本不符    | 本机 Node 不是 22.x     | 使用第 2.1 节临时链                      |
| 安装阶段构建脚本被忽略  | pnpm 11 默认策略        | 检查 `allowBuilds` 是否已包含对应依赖    |
| `Ajv` 无法构造          | NodeNext 下默认导入差异 | 使用命名导入 `import { Ajv } from 'ajv'` |
| 跨包类型解析失败        | 未先构建 `dist`         | 使用根级命令，其内部已先构建             |
| Docker 命令失败         | 本机无 Docker 引擎      | 记录为环境阻塞，不得标注验证通过         |
| PowerShell 引号解析异常 | 多层嵌套引号            | 改用临时脚本文件执行后删除               |
