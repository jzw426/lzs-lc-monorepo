## 3 已完成工作

### 3.1 工程与规范

1. 建立 pnpm workspace 六包结构：core、content、platform、client、server、tools。
2. 锁定 Node.js 22.20.0、pnpm 11.6.0、TypeScript 5.9.3，启用严格模式、`engine-strict` 与 `frozen-lockfile`。
3. ESLint 六包依赖边界规则生效，core 禁止 LayaAir、平台 API、Node API、墙钟时间与非种子随机数。
4. 统一 Prettier、EditorConfig、环境变量样例与根级 `ci` 命令。
5. 根命令 `typecheck`、`test`、`test:coverage`、`validate:content`、`replay:golden` 均先构建，保证干净环境可解析 workspace 产物。

### 3.2 确定性核心与内容

1. xoshiro128\*\* 种子随机数、30 tick/s 模拟循环、规范命令排序、快照续跑与回放校验。
2. 征兵规则固定“容量 → 费用 → 一次随机抽样”，满兵营与费用不足均拒绝且不写经济状态。
3. 内容 Schema、AJV 校验、配置哈希与 4 个兵种基线。
4. 黄金回放固定 `stateHash=fnv1a32:92852f6a`、tick=8、events=6。
5. 平台五类 Port 与 Mock 适配器，未启用能力明确报错，不伪造成功。

### 3.3 服务端与外部依赖

1. Fastify 服务提供健康检查、版本接口、回放校验、统一错误结构与请求追踪。
2. 幂等存储支持内存与 PostgreSQL；同键同体重放、同键异体 409、缺键 400、哈希不符 422。
3. 迁移脚本含校验和防篡改；首次 applied 1 项，复跑 applied 0 项，篡改 exit 1。
4. Docker 多阶段镜像以非 root 运行；PostgreSQL 16.10、Redis 7.4.2、server 三容器均 healthy。
5. 5 并发同键请求全部 200，唯一 stateHash，数据库中该键仅 1 行。

### 3.4 客户端与平台边界

1. `ClientRuntime` 只向视图传递快照与事件，视图异常不影响核心模拟。
2. `assertLayaAirVersion` 固定 LayaAir 3.3.0，版本不一致时直接失败。
3. 五类平台 Port 已定义，抖音适配器尚未落地到实际场景。
4. L3 执行计划已给出 LayaAir 最小场景、抖音适配器与真机接入的完整步骤；v1.1 已按 R-03 评审意见改为场景驱动。

| D-01 | 屏幕方向与设计分辨率     | 默认竖屏 750×1334；如产品定义横屏则整体替换 | 场景与性能基线     |

| D-04 | 性能阈值                 | 批准 L3 计划第 8.1 节建议值                 | 性能判定与复测规则 |
| D-05 | 云端 CI 是否作为 L3 前置 | 建议作为前置，关闭 L2 唯一保留项            | L2 结论完整性      |

## 10 结论

1. M1 工程底座在本地与外部依赖层面已经具备可复核的交付与证据，L1/L2 可以形成“通过”结论。
2. 客户端与真机仍是主要缺口，R-03、R-04、R-05 未关闭，L3 尚未启动。
3. L3 的执行计划、用例与阈值已经就绪，但计划批准、资源确认、云端 CI 与报告签署尚未完成。
4. 在 L3/L4 闭环前，M1 整体不得出具通过结论，也不得对外宣称客户端或生产可用。
5. 当前最优先事项是完成 L3 准入门槛，而不是继续扩展业务玩法。
