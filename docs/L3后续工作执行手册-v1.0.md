### 1.2 步骤 A：AppID 与开放能力配置

3. 成员管理中添加执行人员：
   - R3、R4 至少 2 个账号设置为“开发者”；
   - 另备 1 个账号 B 作为分享接收与交叉验证；
   - 体验者名单覆盖所有测试机登录的抖音号。
4. 开发设置中配置 request 合法域名（HTTPS，已备案）；真机不接受 `localhost` 与 IP。
5. 变现能力中创建激励视频广告位，记录 `adUnitId` 与审核状态。
6. 记录以下信息到 `evidence/L3/<yyyyMMdd>/build/platform-info.txt`：
   - AppID、应用名称、广告位 ID 与状态、域名列表、配置日期、操作人。

完成判定：AppID 可用、至少 2 个测试账号具备权限、广告位状态明确（可用或审核中）。

### 1.3 步骤 B：GUI 发布构建（C-04）

3. 按下表填写发布配置：

| -------- | ------------------------------ |

| AppID    | 开放平台真实 AppID             |

| 构建目录 | `apps/laya-client/dist/douyin` |
| 启动场景 | `Main.ls`                      |
| 屏幕方向 | 竖屏                           |

4. 点击“构建”，等待完成；记录构建日志、耗时、产物总大小与主包大小。
5. 构建完成后复制分享图到包根：


6. 生成产物哈希（E-01 与 R03-08 依赖）：

```powershell
$pkg = 'apps/laya-client/dist/douyin'

  Get-FileHash -Algorithm SHA256 |
  Sort-Object Path |
  ForEach-Object { "$($_.Hash)  $($_.Path)" } |

```

7. 归档到证据目录：`evidence/L3/<yyyyMMdd>/build/`，至少包含 `git-commit.txt`、`build-log.txt`、`douyin-sha256.txt`。

完成判定：IDE 构建退出成功、无缺失资源告警、`dist/douyin` 存在且包含入口 JS 与资源、`share.png` 已在包根、哈希文件非空。

### 1.4 步骤 C：产物校验实跑（E-01）

在仓库根执行（`<AppID>` 替换为真实值）：

```powershell
pnpm run validate:build -- --appid <AppID>
```

脚本逐项校验并输出 JSON，任一项失败退出码为 1：

| 校验项                | 通过标准                                     |
| --------------------- | -------------------------------------------- |
| `game.json`           | 存在、可解析、`deviceOrientation="portrait"` |
| `project.config.json` | 存在、`appid` 非空且与传入值一致             |
| 入口 JS               | 包根存在非空 `.js`                           |
| `share.png`           | PNG、500×400、≤200KB                         |
| `douyin-sha256.txt`   | 存在、非空、含合法 SHA256 行                 |

失败时按提示修复后重跑，禁止手工修改产物绕过校验。校验通过后把输出保存为 `evidence/L3/<yyyyMMdd>/build/validate-build.json`，并回写台账 E-01 为“已完成”。

补充检查（R03-08 需要）：

```powershell
Get-ChildItem apps/laya-client/dist/douyin -Filter *.js | Select-Object Name
Select-String -Path apps/laya-client/dist/douyin/game.json -Pattern '"deviceOrientation"\s*:\s*"portrait"'
Select-String -Path apps/laya-client/dist/douyin/project.config.json -Pattern 'appid'
```

完成判定：`pnpm run validate:build` 退出码 0，五项全为 `ok`，输出已归档。

### 1.6 常见问题排查

| 现象                           | 优先排查                                                         |
| ------------------------------ | ---------------------------------------------------------------- |

### 2.3 步骤 B：代码同步

```powershell
git remote add origin <仓库地址>
git fetch origin
git push -u origin feature/l3-laya-client
```

注意事项：

1. 不得强制推送 `main` 或 `master`。
2. 推送前确认 `git status --short` 干净，且未包含 `dist/`、`engine/types`、本地预览截图之外的临时文件。
3. 若远端已有提交，先 `git pull --rebase origin <分支>`，解决冲突后再推送。
4. 首个 PR 合并到 `main` 后，Actions 才会在 `main` 上产生运行记录。

### 2.4 步骤 C：启用并验证 Actions（E-02）

1. 仓库 Settings → Actions → General，允许 Actions 运行。
2. 确认 `.github/workflows/ci.yml` 使用：
   - `pnpm/action-setup@v4`，版本 11.6.0；
   - `actions/setup-node@v4`，`node-version-file: .nvmrc`；
   - `pnpm install --frozen-lockfile`；
   - 依次执行 format/lint/typecheck/test/coverage/build/validate:content/replay:golden。
3. 触发方式：推送分支或创建 PR。
4. 验收：
   - 工作流状态为绿色；
   - 覆盖率产物 `core-coverage` 可下载；
   - 日志中 `configHash=fnv1a32:e7ae79c0`、`stateHash=fnv1a32:92852f6a`。
5. 保存运行链接与关键日志截图，归档到 `evidence/L3/<yyyyMMdd>/build/ci-cloud.txt`。

### 2.6 常见问题排查

| 现象                                  | 处理                                                                 |
| ------------------------------------- | -------------------------------------------------------------------- |
| `pnpm install --frozen-lockfile` 失败 | lockfile 与 package.json 不一致；本地 `pnpm install` 后提交 lockfile |
| Actions 未触发                        | 工作流不在默认分支或仓库 Actions 被禁用                              |
| format 在云端失败                     | 检查 `.prettierignore` 是否覆盖 IDE 生成物（已配置）                 |
| typecheck 找不到 Laya 类型            | `engine/**/*.d.ts` 未提交或 tsconfig include 缺失                    |
| 覆盖率上传失败                        | `packages/core/coverage` 未生成；确认 `test:coverage` 步骤           |
| 分支保护导致 push 被拒                | 走 PR 流程，不绕过保护                                               |
| 标签推送被拒                          | 确认有 tag 权限；不得删除他人标签                                    |
