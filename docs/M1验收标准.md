## 1 目的与适用范围

本标准规定 M1 阶段工程底座的验收层级、门禁命令、分模块判定条件、指标阈值、证据要求和结论规则。适用于本地工程验收、外部环境联合验收和客户端真机验收，不适用于完整玩法验收。

## 2 验收角色与流程

| 角色            | 职责                                   |
| --------------- | -------------------------------------- |
| 工程底座实施组  | 提交交付物与证据，修复不通过项         |
| QA              | 复核门禁、复现关键路径、核对指标       |
| DevOps          | 提供容器、数据库、缓存与云端流水线环境 |
| 客户端负责人    | 提供 LayaAir 与抖音真机验证证据        |
| 技术负责人      | 判定结论并签署                         |
| 产品/项目负责人 | 确认范围与阶段结论                     |

流程：提交交付物 → 本地门禁复核 → 分模块判定 → 外部环境补验 → 形成结论 → 签署。

## 3 验收层级

| 层级          | 范围                                            | 必要环境                         | 当前状态   |
| ------------- | ----------------------------------------------- | -------------------------------- | ---------- |
| L1 本地工程   | 代码、构建、测试、覆盖率、内容、回放、HTTP 冒烟 | 本机 Node 22.20.0 与 pnpm 11.6.0 | 已具备证据 |
| L2 外部环境   | 容器、PostgreSQL、Redis、云端 CI                | Docker 引擎与依赖服务            | 未执行     |
| L3 客户端真机 | LayaAir 场景、抖音开发者工具、三档真机          | 引擎与设备                       | 未执行     |
| L4 生产       | 部署、迁移、监控、回滚                          | staging/production               | 未执行     |

**判定原则：层级之间不可替代。** L1 通过不代表 L2 或 L3 通过；未执行项一律记为“待验收”，不得记为“通过”。

## 4 通用门禁标准

### 4.1 必过命令

```text
npx --yes --package=node@22.20.0 --package=pnpm@11.6.0 --call "pnpm run ci"
```

该命令依次执行格式检查、Lint、类型检查、测试、覆盖率、构建、内容校验和黄金回放，任一步失败即判定 L1 不通过。

### 4.2 门禁判定表

| 检查项   | 通过条件                                  |
| -------- | ----------------------------------------- |
| 格式检查 | Prettier 无差异                           |
| Lint     | ESLint 零错误，含依赖边界与 core 禁用规则 |
| 类型检查 | 六包 `tsc --noEmit` 全部通过              |
| 测试     | 全部通过，无跳过、无待定                  |
| 覆盖率   | 达到第 5 节阈值                           |
| 构建     | 六包产物生成成功                          |
| 内容校验 | 返回 `status: ok` 且哈希与清单一致        |
| 黄金回放 | 返回 `status: ok` 且哈希与样本一致        |

## 5 指标阈值

| 指标            | 阈值                          | 判定方式       |
| --------------- | ----------------------------- | -------------- |
| core 语句覆盖率 | ≥ 90%                         | 覆盖率报告     |
| core 行覆盖率   | ≥ 90%                         | 覆盖率报告     |
| core 分支覆盖率 | ≥ 85%                         | 覆盖率报告     |
| core 函数覆盖率 | ≥ 90%                         | 覆盖率报告     |
| 征兵模块覆盖    | 语句、分支、函数、行均为 100% | 覆盖率报告     |
| 测试失败数      | 0                             | 测试输出       |
| 黄金回放一致性  | 哈希完全一致                  | CLI 输出       |
| 内容哈希一致性  | 与清单完全一致                | CLI 输出       |
| 服务就绪检查    | 返回 200                      | 真实 HTTP 请求 |
| 幂等重试        | 返回一致结果且标记为重放      | 真实 HTTP 请求 |
| 版本不一致      | 返回 409                      | 接口测试       |
| 回放分歧        | 返回 422                      | 接口测试       |

当前基线参考值：测试 73 项、core 语句与行覆盖率 99.39%、分支 97.11%、函数 100%、`configHash=fnv1a32:e7ae79c0`、黄金 `stateHash=fnv1a32:92852f6a`。后续变更不得使指标低于阈值，测试数量不得无故减少。

## 7 结论判定规则

| 结论       | 条件                                         |
| ---------- | -------------------------------------------- |
| 通过       | 对应层级全部检查项满足，证据可复核           |
| 有条件通过 | 非关键项存在缺口，且已登记责任方与关闭期限   |
| 不通过     | 关键项失败，或存在伪造、缺失、无法复现的证据 |
| 待验收     | 未执行或环境不可用，不得给出通过结论         |

关键项包括：构建与类型、测试全通过、覆盖率达标、确定性回放一致、内容校验一致、服务启动与就绪、版本与幂等校验、范围声明真实。

## 8 证据留存要求

1. 保留命令原文、退出码与关键输出，不只保留结论截图。
2. 覆盖率报告、测试统计与哈希值必须可复现。
3. 外部环境证据需包含环境标识、依赖版本与执行时间。
4. 真机证据需包含设备型号、系统版本、引擎版本与采样数据。
5. 证据与报告版本对应，变更后重新采集，不得复用旧结论。

## 10 不通过处理

1. 关键项失败时冻结阶段结论，修复后重新执行完整门禁。
2. 非关键项失败可登记为遗留项，但必须明确责任方、关闭标准与复核时间。
3. 环境阻塞应记录原始错误信息，不得通过降低标准规避。
4. 任何结论变更需更新验收报告版本并保留历史记录。
