目标：建立可构建、可测试、可回放、可部署、可回滚的工程底座，为M2战斗内核及后续内容生产提供统一约束。

适用阶段M1及后续继承
客户端LayaAir 3.x / TypeScript
服务端Node.js LTS / Fastify

版本原则：所有“3.x、5.x、LTS”在技术评审时必须落为精确版本并写入锁文件或运行时配置；构建环境禁止使用浮动最新版。本文不将参考游戏未公开的内部实现当作本项目约束。

1. 技术约束与选型优先级

  1. 确定性优先：同配置、种子和输入必须得到同结果，优先于表现便利。
  2. 小游戏适配优先：包体、内存、触摸和生命周期优先于通用引擎功能数量。
  3. 核心复用优先：战斗内核同时运行于客户端、测试工具和服务端校验。
  4. 简单完整优先：首发采用模块化单体，不为未来假设引入微服务和消息队列。
  5. 可恢复优先：构建、配置、数据库和资源发布均需可追踪、可回滚。

3. 中间件选型

中间件建议选型依据优势对比适用场景风险预案
HTTP框架Fastify轻量、schema友好、TS生态成熟，符合模块化单体相较NestJS启动与结构更轻；相较原生HTTP具备路由、校验和插件边界登录会话、对局、商店、结算、配置接口插件版本锁定；统一错误码和超时。若团队已有NestJS规范可替换，但不得同时维护两套HTTP体系
持久化数据库PostgreSQL玩家、对局、奖励、武器和流水需要事务与唯一约束相较仅Redis可可靠持久化；相较文档数据库更适合幂等键、关系与对账账户、档案、对局摘要、奖励流水、运营配置版本每日备份与恢复演练；迁移采用expand→migrate→contract。奖励幂等最终由数据库唯一约束兜底
缓存与限流Redis会话、短期锁、限流和热点配置需要低延迟相较进程内存支持多实例；不替代数据库事实源会话缓存、接口限流、配置缓存、短期分布式锁Redis故障时关闭非必要缓存并限流；不得因缓存丢失重复发奖。核心结算回源数据库
消息与异步任务首发不引入MQ，使用数据库事务外盒（Outbox）当前异步任务量有限，可靠性优先于基础设施数量相较直接“库写一半再发消息”可避免丢失；相较Kafka/RabbitMQ运维更轻结算后排行更新、埋点补发、非实时通知设置重试、死信记录和人工重放入口；任务幂等。确有吞吐证据后再评估MQ
资源分发对象存储 + CDN + 内容hash清单动画、音频和活动资源不应全部进入首包相较固定服务器目录具备缓存、版本和回滚能力分包外大资源、活动图、音频和版本化内容资源以hash不可变发布；CDN失败重试备用域名或包内核心资源；旧清单不得立即删除旧资源
日志与追踪Pino + OpenTelemetry需要结构化日志、对局ID串联和性能定位相较零散console日志可检索、可采样、可跨服务关联API、结算、构建、加载、慢查询和异常日志脱敏与采样；监控系统故障不得阻塞战斗。禁止记录凭证、完整个人信息和广告敏感参数

4. 架构模式

架构决策建议选型依据优势对比适用场景风险预案
总体形态单仓 + 模块化单体服务小团队首发、共享核心和配置，边界清晰但避免分布式复杂度相较微服务减少部署与调试成本；相较单文件项目仍可独立测试模块client/core/server/content/tools/platform六包模块依赖由lint规则限制；只有稳定边界和独立扩容证据才允许拆服务
战斗核心纯逻辑、固定30 tick/s、命令输入、事件输出保证回放和服务端复用相较渲染驱动逻辑不受FPS、广告和动画影响移动、索敌、攻击、波次、合成和结算掉帧只补逻辑tick并限制单帧追赶上限；绝不通过跳 tick 改结果。性能不足时优化逻辑或降渲染
确定性数值整数tick、整数最小单位、定点位置、规范排序避免wall-clock、对象遍历和浮点误差导致分歧相较浮点秒计时更适合状态hash与服务端重放资源、生命、伤害、冷却、路径和实体排序禁止核心调用Date.now/Math.random；发现除法或取整差异时集中定义舍入规则并加跨运行时测试
随机数xoshiro128**或评审批准的等价32位算法，显式种子需要跨Node与小游戏端一致的位运算和可复现序列相较Math.random可回放；相较每次请求服务端随机更易重放整个对局征兵、字牌、道具和经批准的Boss随机算法与版本写入对局头；升级算法不改变旧对局。卡池顺序和抽样次数固定，禁止表现层消耗随机数
战斗事件有序事件队列 + 统一伤害/结算管线技能、Buff和道具组合需要一致顺序相较各单位自行扣血可减少重复死亡和顺序歧义命中、控制、死亡、资源、经验、突破和胜负顺序固定为tick→阶段→实体ID→事件序号；新增事件必须附顺序测试与旧回放回归
表现架构状态快照/事件驱动View，View只读核心避免动画和UI修改战斗数据相较双向绑定更易暂停、降级和回放汉字、Tween、Spine、音效、伤害数字用依赖检查禁止core引用Laya对象；表现异常仅降级表现，不得重置核心
平台架构Port/Adapter适配器 + 本地Mock抖音首发且保留微信适配，测试需脱离平台相较业务代码散布tt调用，差异集中且可测试登录、广告、分享、存储、生命周期、分包平台API变化只修改适配器；无平台能力时明确失败，不伪造成功回调
服务接口HTTPS REST/JSON，版本化，数据库事务保证结算首发异步对局无需持续连接相较WebSocket更易缓存、追踪、重试和扩容配置、对局创建、结算、商店和档案请求带requestId/idempotencyKey；超时重试必须使用同键。真实时需求出现时另行架构评审
配置与回放版本gameVersion + contentVersion + rulesVersion + configHash旧对局与历史内容必须可解释相较单一版本号能区分代码、规则和内容变化发布、结算、回放、客服排查版本不兼容时拒绝结算或进入明确无效对局；不得加载半套新旧配置

4.1 推荐单仓边界

packages/
  core/       纯TypeScript战斗、随机、命令、事件、快照；禁止Laya与平台API
  client/     LayaAir场景、输入、动画、音频；只通过端口调用core
  server/     Fastify接口、数据库、结算与回放校验
  content/    JSON、Schema、内容校验与版本清单
  tools/      模拟器、配置导出、压力测试、构建工具
  platform/   抖音/微信Adapter及Mock

5. 开发规范

规范项强制规则依据与优势适用场景风险预案
代码与注释TypeScript strict；公开接口必须有类型；业务注释使用中文；禁止无说明any、魔法数字和隐式全局状态减少跨模块歧义，便于AI与人工共同维护全部包临时例外必须写原因、责任人和移除条件；CI统计例外不得持续增加
模块依赖依赖方向只允许client/server/tools→core/content、client→platform；core不得依赖client/server/platform保持核心可复用与可测试PR静态检查违规即构建失败；确需调整必须技术评审而非绕过规则
配置规范内容ID稳定不可复用；数值有单位、范围、默认值和版本；禁止删除仍被历史回放引用的内容保证内容与旧对局可追踪全部武将、技能、地图和运营配置Schema及引用检查；缺失资源/引用阻断发布
Git与评审短分支+小PR；Conventional Commits；功能、格式化和依赖升级分开；核心战斗至少2名评审，其余至少1名降低合并和回归成本所有人工及AI生成代码AI产出与人工同门禁；不得自我生成后直接合入。紧急修复需补回归测试
测试门禁core行覆盖率≥90%、分支≥85%；经济、合成、拼字、突破、结算关键分支100%；所有随机失败记录种子优先覆盖高风险规则而非追求全项目数字PR、 nightly模拟和发布覆盖不足阻断合入；禁止通过排除关键文件达标
回放与回归核心逻辑PR必须运行固定黄金回放集；预期结果变化必须附规则变更编号和新基线区分合法规则调整与非预期行为变化战斗、数值、动画隔离测试不得直接批量更新快照而无人工差异说明
安全与密钥密钥只进入环境密钥管理；仓库禁止token、数据库密码和广告私密配置；日志脱敏降低泄露与合规风险本地、CI、测试、生产发现泄露立即吊销轮换并清理历史；不得只删除当前文件后继续上线
文档与ADR每项影响核心规则、数据格式、部署或依赖升级的决策写简短ADR，关联REQ/DEC编号防止技术实现静默改变需求技术评审和变更无ADR不得变更已冻结协议；文档与代码同PR更新

6. 部署方案

6.1 环境与发布链

项目建议方案依据与优势适用场景风险预案
环境划分local、test、staging、production四环境；账户、数据库、存储、广告位和密钥完全隔离避免测试数据污染生产，支持发布前等效验证开发、回归、预发和正式配置按环境注入；启动时输出环境与非敏感版本信息，禁止生产误连测试广告/数据库
本地依赖容器化PostgreSQL/Redis；core与content测试不强制启动容器统一依赖版本，同时保持核心测试轻量服务端联调和集成测试提供一键初始化与清空脚本；不得使用生产数据作为本地默认数据
服务端部署Node.js服务构建为不可变容器；生产优先托管PostgreSQL/Redis；多实例无本地会话事实源便于滚动发布、扩容和恢复API、结算、配置和后台任务健康检查未通过不切入流量；实例退出前完成请求排水；后台任务使用可重入幂等设计
小游戏构建锁定LayaAir构建环境的专用CI runner；产物包含精确引擎、代码、内容和资源版本避免不同开发机产生不可解释差异抖音测试包、体验包与正式包若引擎CLI不支持某构建步骤，保留受控专用构建机并上传校验hash；不得手工修改产物后直发
CI门禁安装→类型/依赖检查→lint→单测/性质测试→Schema→黄金回放→服务端集成→构建→包体与产物hash任何阶段失败均不产生可发布候选PR、主分支与发布标签缓存仅按锁文件和工具版本复用；异常时清理缓存重建，不允许跳过重放和测试
资源发布先上传hash资源，再发布配置清单，最后切换客户端可见版本；旧资源保留至旧对局与缓存窗口结束避免清单先于资源导致404动画、音频、活动及内容更新CDN校验失败即停止切换；回滚只回指旧清单，核心包内资源始终可启动
数据库发布向后兼容的expand→migrate→contract；迁移与代码发布解耦支持滚动升级和回滚玩家、流水、武器、商店等结构变更破坏性变更至少跨越兼容版本；迁移前备份并验证恢复；失败时停止发布而非反复执行
服务回滚不可变镜像与配置版本绑定；采用滚动或蓝绿切换；数据库事实源不回滚到不兼容旧结构缩短故障定位与恢复路径异常结算、加载失败或严重性能回退无法兼容时优先关闭新功能/新配置并维持服务；禁止直接恢复数据库备份覆盖新流水
监控告警启动成功率、API错误率、P95延迟、结算冲突、回放不一致、资源404、广告异常和任务积压覆盖核心闭环而非仅CPU预发和上线告警带版本、环境、对局/请求ID；监控不可用时启用保守发布，不继续扩大流量

7. 综合风险登记

风险触发信号预防应急处置
客户端/服务端战斗分歧同回放hash不同共享core、整数tick、跨运行时黄金用例暂停相关版本结算，保留种子与事件流，回退共同可用版本
引擎或平台升级破坏构建CI或真机启动失败锁版本、专用runner、升级独立分支回退引擎/基础库与上一不可变产物
配置或资源不兼容Schema失败、hash不符、CDN404原子清单、引用校验、先资源后清单回退包内基线或旧清单，禁止加载半套内容
重复结算/广告奖励同对局或请求产生多条有效流水数据库唯一约束、幂等键、状态机冻结异常奖励入口，按流水对账与补偿，不重跑整个对局
Node服务性能不足P95持续超标且CPU/事件循环饱和压测、异步I/O、避免JSON大对象复制限流与水平扩容；有证据后再拆独立回放计算worker
AI生成代码引入隐性规则变化黄金回放差异、无REQ/ADR的新行为同人工评审、测试和依赖约束回退PR，补最小复现和规则测试，不接受仅修改快照
